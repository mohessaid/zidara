# The server and PostgreSQL

Distilled from Supabase's Postgres best practices (security, schema, connections, data
access), applied to Zidara's design. Before writing schema or SQL, check every rule here.

## Isolation is a data rule

- Every table that holds learner data carries `tenant_id` and `cohort_id`.
- Enable and **force** row-level security on every such table:
  ```sql
  alter table events enable row level security;
  alter table events force row level security;
  ```
- The app connects as `zidara_app`, a non-owner login role without `BYPASSRLS`. Migrations
  run as a separate owner role. Never connect the app as owner or superuser.
- Each request opens a transaction and sets its context with `SET LOCAL` (it dies with the
  transaction, so a pooled connection cannot leak it):
  ```sql
  select set_config('app.tenant_id', $1, true),
         set_config('app.cohort_ids', $2, true),   -- comma-separated uuids
         set_config('app.user_id', $3, true);
  ```
- Write policies so the settings are read once per query, not once per row: wrap them in a
  scalar subquery.
  ```sql
  create policy events_cohort on events for all to zidara_app
    using (tenant_id = (select current_setting('app.tenant_id', true)::uuid)
       and cohort_id = any ((select string_to_array(current_setting('app.cohort_ids', true), ',')::uuid[])));
  ```
  A missing setting must yield **no rows**, never all rows. Integration tests prove it.
- Least privilege: on `events`, `zidara_app` gets `SELECT, INSERT` only, with no `UPDATE`
  or `DELETE`. The log is append-only in the database too.

## Schema

- Primary keys are UUIDv7, generated by the app (time-ordered, so no index fragmentation).
- Index every foreign key column. Postgres does not do it for you.
- Use `timestamptz` for times, `jsonb` for event bodies (the kernel's serde JSON), `text` with
  `check` constraints for small enums, and constraints for every invariant the database can hold.
- Lowercase snake_case identifiers.
- `applied_envelopes (id uuid primary key, cohort_id, applied_at)` makes sync idempotent:
  `insert ... on conflict (id) do nothing returning id`. Zero rows returned means already
  applied, so skip it.

## Requests

- Keep transactions short. **Never call the model inside a transaction.** Flow for an open
  answer:
  1. commit the `AnswerSubmitted` event;
  2. call the assessor outside any transaction;
  3. open a new transaction for `ProposeAssessment`.
- `decide` needs the cohort's history. Load it with one query ordered by `at`, never one query
  per learner (no N+1).
- List endpoints use keyset pagination (`where (at, id) > ($1, $2) order by at, id limit $3`),
  never `OFFSET`.
- Insert a command's events with a single multi-row `INSERT`.

## Connections

- One pool per process (sqlx `PgPool`). Size it from measurement, starting near
  `cores * 2`.
- Behind PgBouncer in transaction mode, prepared statements break unless PgBouncer is 1.21 or
  later with `max_prepared_statements` set, or the sqlx statement cache is disabled.
- Set `statement_timeout`, and `idle_in_transaction_session_timeout` on the app role.

## Tests that prove isolation (integration, real PostgreSQL in Docker)

- A user in cohort A reads 0 rows of cohort B through the API, through raw SQL with A's
  settings, and with no settings at all.
- The agent's requests are bound by the same policies.
- `UPDATE` and `DELETE` on `events` fail for `zidara_app`.
- Replaying the same envelope twice appends once.
- Use `testcontainers` or the Compose service. The container stops when the tests end, with
  no restart policy.
