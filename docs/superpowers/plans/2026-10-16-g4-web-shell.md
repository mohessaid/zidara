# G4: The Web Shell — Implementation Plan

> Executed inline, TDD per task. Skills: `zidara` (web-shell, accessibility, game-design),
> `girth-wasm`. Art: `docs/art-bible.md`.

**Goal:** an installable, offline-first web app. Learners play the lesson as a Quest (or see a
Grid); teachers run the studio. All of it runs on the kernel in wasm and syncs through the
command API.

**Stack:** Vite 8, Svelte 5.57 (runes), TypeScript 6.0 (svelte-check supports 5–6, not 7),
PixiJS 8.22 (map), GSAP 3.15 (motion), idb 8 (IndexedDB), vite-plugin-pwa 2. Tests: Vitest 5
(+ fake-indexeddb), Playwright 1.64 + @axe-core/playwright 4.14, Lighthouse 13. pnpm.

**Layout:**
- `web/src/lib/kernel/`: generated `types/`, built `pkg/`, and `kernel.ts`, a typed wrapper
  over `Shell`.
- `web/src/lib/store.ts`: IndexedDB holding the session, the log and the outbox.
- `web/src/lib/sync.ts`: posts the outbox, pages `/events`, and calls `shell.load`.
- `web/src/lib/api.ts`: a typed fetch client.
- `web/src/lib/i18n/`: `ar`, `fr` and `en` strings; `dir` and `lang` on `<html>`.
- `web/src/screens/`: `SignIn`, `Quest` (PixiJS + DOM twins), `Grid`, `Activity` (video,
  reading, quiz, open response), `Studio`.
- `web/tests/unit/` (Vitest), `web/tests/e2e/` (Playwright against the real server via the
  `vite preview` proxy).

**Rules carried in:**
- Learner screens never show queued agent proposals.
- Every canvas node has a DOM twin with a name, state and lock reason.
- Every state is colour, shape and words.
- Touch targets are 48 px.
- `prefers-reduced-motion` is honoured.
- The device clock is passed as `nowMs`.
- Envelope ids come from `crypto.randomUUID()`.

**Done when (GOALS G4):** Playwright proves:
- offline lesson then sync (the server holds the work);
- a teacher accepts a queued answer;
- a framework switch redraws the map;
- a learner of cohort B cannot see cohort A;
- the Arabic UI is RTL.

Also:
- axe reports 0 violations on every screen;
- the map holds 60 fps under a 4× CPU throttle;
- Lighthouse scores ≥ 90 for performance and 100 for accessibility.

## Tasks
1. Scaffold, plus `kernel.ts` with Vitest tests that load the real web-target wasm in Node.
2. `store.ts` and `sync.ts`, tested with fake-indexeddb and a fake server: the outbox
   survives a reload, sync is idempotent, and a refused command is dropped with its reason kept.
3. i18n and the app shell: sign-in, routing, and locale with `dir`.
4. The lesson player: activities and quiz input, recording through the kernel offline.
5. The Quest map (PixiJS) with DOM twins, and the Grid experience.
6. The studio: the queue (accept/reject), flags, agent actions with undo, and the framework
   switch.
7. PWA: the service worker precaches the shell, the wasm and the pack.
8. E2E, axe, fps and Lighthouse; then the record; tag `g4-web`.
