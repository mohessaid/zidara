# G2 / M2: The Server — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Steps use
> checkboxes. Tests are specified exactly; implementation is settled by TDD against the
> compiler. sqlx 0.9 and axum 0.8 details are verified there, not guessed here.

**Goal:** an axum server on PostgreSQL 16 that runs the kernel for every change, with isolation
enforced by the database, idempotent command replay, and a governed assessor agent.

**Architecture:** `crates/zidara-server` is a shell around the pure kernel. Each request opens
one short transaction:
1. `SET LOCAL app.user_id`;
2. take a per-cohort advisory lock;
3. record the envelope id (`ON CONFLICT DO NOTHING`);
4. load the history the user may see;
5. run `decide`;
6. insert the events;
7. commit.

The database decides what a user sees from `memberships`, through RLS. The assessor runs
outside any transaction, then acts as an agent user through the same command path.

**Tech:** axum 0.8, sqlx 0.9 (runtime queries, `migrate!` for embedded migrations), tokio,
jsonwebtoken 11 (demo sign-in), reqwest 0.13 (Claude), uuid v7, testcontainers-modules 0.15
(PostgreSQL 16) for tests, wiremock 0.6 for the fake Claude API.

**Spec:** `docs/superpowers/specs/2026-10-14-zidara-prototype-design.md` §3.5, §3.6, §4.
**Skill:** `.claude/skills/zidara/references/postgres.md`.

## Global Constraints

- The app connects as `zidara_app`: a non-owner role with no `BYPASSRLS`. The only context it
  sets is `app.user_id`, with `SET LOCAL` inside a transaction.
- Policies read settings through `nullif(current_setting('app.user_id', true), '')::uuid` and
  return no rows when the setting is unset.
- `events` and `applied_envelopes`: `zidara_app` has `SELECT, INSERT` only.
- Never call the model inside a transaction.
- `at` = envelope.at, clamped between the sender's latest event time and server now. The
  history read happens after the advisory lock at READ COMMITTED (the default), so it sees
  the other command's committed events.
- Learners see only events about themselves (`learner_id = me`) plus cohort-wide events
  (`learner_id is null`). Teachers and agents see their cohort. Nobody sees other cohorts.
- Tests run against real PostgreSQL 16 in a container that is removed when the tests end.
- Commit style, changelog and journal as in `AGENTS.md`.

## Review Focus

1. A pooled connection that served cohort A, then serves a request with no context, must see
   nothing. (Test: `a_reused_connection_without_context_sees_nothing`.)
2. Two commands for one cohort at the same moment must not both assign remediation.
   (Test: `concurrent_weak_attempts_assign_remediation_once`.)
3. An envelope dated in the future is capped at server time; one dated before the sender's
   latest event is floored to it, so a modified client cannot push weak attempts out of the
   mastery window; a replayed envelope applies once. (Tests: `future_dated_envelopes_are_capped`,
   `backdated_envelopes_are_floored`, `replayed_envelope_applies_once`.)
4. A learner's client asking for another learner's view or the studio gets 403, not data.
   (Test: `learners_cannot_open_the_studio_or_other_cohorts`.)
6. A learner can read the agent's provisional mark (ProposalMade carries their learner_id).
   Correct for sync; the Quest (G4) must not render queued proposals.
5. When the Claude API times out or returns nonsense, the answer is still marked, but is never
   auto-applied. (Test: `a_failing_model_falls_back_and_queues`.)

### Task 1: Schema, roles and RLS, proven against real PostgreSQL

**Produces:** `migrations/0001_init.sql`; `tests/support::{TestDb, db().await}`, where
`TestDb { owner: PgPool, app: PgPool, seed: Seed }` gives each test a fresh database with
migrations applied and the demo seed. `seed::Seed` holds the ids of: tenant; cohorts `a`
and `b`; learners `amina`, `yacine` (in a) and `sara` (in b); teachers `karim` (a) and `nadia` (b);
`agent` (member of a and b as `assessment_agent`).

Schema (exact):

```sql
create schema if not exists private;

-- Roles are cluster-wide; parallel test databases race on this, hence the handler.
-- The password is set outside migrations (ops, or tests/support once per container).
do $$ begin
  create role zidara_app login nobypassrls;
exception when duplicate_object then null;
end $$;

create table tenants (id uuid primary key, name text not null);
create table cohorts (
  id uuid primary key,
  tenant_id uuid not null references tenants(id),
  name text not null,
  lesson_id text not null,
  framework text not null
);
create index cohorts_tenant_id_idx on cohorts (tenant_id);
create table users (
  id uuid primary key,
  tenant_id uuid not null references tenants(id),
  display_name text not null,
  kind text not null check (kind in ('person', 'agent'))
);
create index users_tenant_id_idx on users (tenant_id);
create table memberships (
  user_id uuid not null references users(id),
  cohort_id uuid not null references cohorts(id),
  role text not null check (role in ('learner', 'teacher', 'assessment_agent')),
  primary key (user_id, cohort_id)
);
create index memberships_cohort_id_idx on memberships (cohort_id);
create table events (
  seq bigint generated always as identity primary key,
  id uuid not null unique,
  tenant_id uuid not null references tenants(id),
  cohort_id uuid not null references cohorts(id),
  learner_id uuid references users(id),
  at_ms bigint not null,
  actor jsonb not null,
  body jsonb not null
);
create index events_cohort_order_idx on events (cohort_id, at_ms, seq);
create index events_tenant_id_idx on events (tenant_id);
create index events_learner_id_idx on events (learner_id);
create table applied_envelopes (
  id uuid primary key,
  tenant_id uuid not null references tenants(id),
  cohort_id uuid not null references cohorts(id),
  user_id uuid not null references users(id),
  applied_at timestamptz not null default now()
);
create index applied_envelopes_tenant_id_idx on applied_envelopes (tenant_id);
create index applied_envelopes_cohort_id_idx on applied_envelopes (cohort_id);
create index applied_envelopes_user_id_idx on applied_envelopes (user_id);

create function private.me() returns uuid language sql stable
  as $$ select nullif(current_setting('app.user_id', true), '')::uuid $$;
-- security definer: reads memberships without RLS, so policies on memberships do not recurse.
create function private.my_cohorts() returns setof uuid language sql stable security definer
  set search_path = '' as $$
  select m.cohort_id from public.memberships m where m.user_id = private.me() $$;
create function private.overseen_cohorts() returns setof uuid language sql stable security definer
  set search_path = '' as $$
  select m.cohort_id from public.memberships m
  where m.user_id = private.me() and m.role in ('teacher', 'assessment_agent') $$;

alter table tenants enable row level security;          alter table tenants force row level security;
alter table cohorts enable row level security;          alter table cohorts force row level security;
alter table users enable row level security;            alter table users force row level security;
alter table memberships enable row level security;      alter table memberships force row level security;
alter table events enable row level security;           alter table events force row level security;
alter table applied_envelopes enable row level security; alter table applied_envelopes force row level security;

create policy cohorts_mine on cohorts for select to zidara_app
  using (id in (select private.my_cohorts()));
create policy tenants_mine on tenants for select to zidara_app
  using (id in (select c.tenant_id from cohorts c));
-- Data minimisation: learners see their own rows only; overseers see their cohorts'.
create policy memberships_mine on memberships for select to zidara_app
  using (user_id = (select private.me()) or cohort_id in (select private.overseen_cohorts()));
create policy users_mine on users for select to zidara_app
  using (id = (select private.me()) or id in (select m.user_id from memberships m));
create policy events_read on events for select to zidara_app
  using (cohort_id in (select private.my_cohorts())
         and (learner_id is null or learner_id = (select private.me())
              or cohort_id in (select private.overseen_cohorts())));
create policy events_write on events for insert to zidara_app
  with check (cohort_id in (select private.my_cohorts())
              and (learner_id is null or learner_id = (select private.me())
                   or cohort_id in (select private.overseen_cohorts())));
create policy envelopes_mine on applied_envelopes for all to zidara_app
  using (user_id = (select private.me()))
  with check (user_id = (select private.me()) and cohort_id in (select private.my_cohorts()));

grant usage on schema public, private to zidara_app;
grant execute on all functions in schema private to zidara_app;
grant select on tenants, cohorts, users, memberships to zidara_app;
grant select, insert on events, applied_envelopes to zidara_app;
```

Note the `learner_id is null` branch of `events_write`. It exists for cohort-wide events such
as `FrameworkChanged`. The kernel's permission table already stops a learner from issuing
those; the database adds a second wall for learner-specific rows.

### Task 3: Commands — the one write path

**Produces:** `commands::apply(pool, &AppState, user: UserId, cohort: CohortId, Envelope)
-> Result<Outcome, ApiError>` with `Outcome::{Applied { events: Vec<Event> }, Duplicate,
Refused(KernelError)}`.

Steps, in one transaction:
1. Set the context.
2. `pg_advisory_xact_lock(hashtextextended(cohort::text, 0))`.
3. Look up the membership role (none → `ApiError::NotMember`).
4. `insert into applied_envelopes … on conflict do nothing returning id` (no row →
   `Duplicate`, commit).
5. Load the cohort (lesson, framework) and the visible history, ordered `at_ms, seq`.
6. Build `Actor` (person → `Human`; agent → `Agent { agent: AgentId(display_name) }`) and
   `Env` with `now = clamp(envelope.at, sender's latest at_ms, clock.now())`.
7. `decide`: `Err` → rollback and `Refused`.
8. Insert all events in one statement, with `learner_id` from `visibility`.
9. Commit.

Tests (`tests/commands.rs`, real database):
- `a_learners_quiz_is_marked_and_stored`: one envelope → `Applied` with 2 events; the history
  holds them; `learner_id` = Amina.
- `replayed_envelope_applies_once`: same envelope twice → `Applied`, then `Duplicate`; one
  `QuizSubmitted` in the log.
- `refused_commands_leave_no_trace`: a learner's `ChangeFramework` → `Refused(Forbidden)`; no
  events and no envelope row; resending the same id is refused again, not `Duplicate`.
- `future_dated_envelopes_are_capped`: `at` = now + 1 day → stored `at_ms` = clock now.
- `backdated_envelopes_are_floored`: after an attempt at t, an envelope dated t − 1 day is
  stored at t.
- `concurrent_weak_attempts_assign_remediation_once`: Amina has 1 weak F2 attempt; send 2 weak
  attempts concurrently (`tokio::join!`, two pool connections) → exactly 1 `ActivityAssigned`.
- `non_members_are_refused`: Sara sending to cohort a → `NotMember`.
- `the_teacher_sees_what_the_learner_did`: after Amina's quiz, the studio view (Task 6) built
  from Karim's visible history counts her.

### Task 4: The assessor (Rubric and Claude) and the agent

Read the `claude-api` skill before writing `Claude`.

**Produces:** `assessor::Assessor::{Rubric, Claude(ClaudeClient)}` with
`async fn assess(&self, &Rubric, &str, locale: &str) -> Assessment`. `Claude` calls the
Messages API (model `claude-haiku-5-5`, a short system prompt carrying the rubric, structured
JSON output `{score_bp, confidence_bp, rationale}`). On any error, timeout (10 s) or
out-of-range value, it falls back to the rubric and caps confidence at `MIXED`, so a teacher
reviews it. `agent::mark_pending(state, cohort)` finds answers with no proposal in the agent's
visible history and, for each, calls `assess` (no transaction open), then sends
`ProposeAssessment` through `commands::apply` as the agent user.

Tests (`tests/assessor.rs`, wiremock for the API):
- `claude_scores_are_parsed`: a mocked reply gives the exact `Assessment`, and the request
  carries the model id, the rubric and the answer.
- `a_failing_model_falls_back_and_queues`: 500, timeout, malformed JSON, and a score above
  10 000 each yield the rubric's score with confidence ≤ `MIXED`.
- `the_agent_marks_each_answer_once`: two answers → two proposals; a second run makes none.
- `a_confident_mark_is_applied_and_an_unsure_one_queued`: end to end through the rubric
  assessor and the real database.
- Rubric word boundaries (deferred minor), as a kernel change, test first in
  `crates/zidara-kernel/tests/governance.rs`. Latin-script terms match at word starts, so
  "sesame" no longer matches "same" and "sometimes" no longer matches "times". Arabic-script
  terms keep substring matching, because roots sit inside conjugated words (`ضرب` in `نضرب`).
  Pin both cases before changing `assess`.
