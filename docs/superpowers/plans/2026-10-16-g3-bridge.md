# G3: The Kernel in the Browser — Implementation Plan

> Executed inline (superpowers:executing-plans), TDD per task. Skills: `zidara`, `girth-wasm`.

**Goal:** the web shell runs the same kernel as the server, offline, through a small typed
bridge, with proof that phone and server compute the same thing.

**Architecture:** `crates/zidara-wasm` has two layers.
- `Core`: plain Rust and native-testable. It holds the lesson, the frameworks, the cohort
  identity and the local event log. `run(actor, envelope)` calls `decide` and appends to the log.
- `Shell`: a thin `#[wasm_bindgen]` wrapper that passes JSON strings across. JSON was chosen
  because the kernel already speaks serde JSON and the server's API uses the same shapes;
  one format means one contract.

IndexedDB persistence and the outbox stay in TypeScript (G4).

**Decisions:**
- **Ids without randomness.** Event ids are derived from the envelope id, which JS makes with
  `crypto.randomUUID()`: `base + n`. They are provisional; the server re-derives everything
  on sync and the shell replaces its log (ADR 0005).
- **Time.** `env.now` is `envelope.at`.
- **Idempotency.** The phone keeps the applied envelope ids too, so a double tap that reuses
  an id is a no-op locally, as on the server.
- **Types.** `ts-rs` derives sit on the kernel types behind a `ts` feature. They are exported
  to `web/src/lib/kernel/types/` and checked in. `make types` regenerates them, and
  `git diff --exit-code` proves they are fresh.

**Done when (G3):**
- `Core` is fully covered, with all mutants caught.
- The wasm `Shell` passes its tests on wasm32.
- A golden session, produced by the native `Core` and replayed in Node through the
  `--target nodejs` build, yields byte-identical views.
- The `.wasm` size (raw and gzipped, `--target web`, release) is recorded.

## Tasks
1. `Core` (native TDD), covering:
   - a quiz run returns events;
   - refusals come back as `{status: "refused", error}`;
   - a duplicate envelope id is a no-op;
   - `load` replaces the log;
   - learner and studio views;
   - a bad JSON input is an error, not a panic;
   - derived ids are distinct and stable.
2. `Shell` wrapper and wasm32 tests; add the crate to `make wasm targets`.
3. `scripts/build-wasm.sh`: release build, wasm-bindgen `web` and `nodejs`, wasm-opt if
   present, and sizes printed.
4. The golden session: native writes `crates/zidara-wasm/tests/golden/session.json` (`make
   golden`); `web/tests/bridge.test.mjs` (node:test) replays it through the Node build.
5. ts-rs types for the boundary (Command, Envelope, Event, views, Actor, Lesson), plus
   `make types`.
6. Record: CHANGELOG, JOURNAL, the skill. Tag `g3-bridge`.
